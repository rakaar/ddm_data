## How the scheduled-timing row matching works

The implementation uses `networkx.network_simplex`, an integer minimum-cost-flow solver. It does **not** receive a DataFrame and does **not** directly return rows to keep or remove. It receives a directed graph whose nodes and edges encode the requested timing distributions and the timing combinations actually available in session types 7 or 8.

### Inputs given to `network_simplex`

First, the pooled session-type-9 trials are converted into separate 20 ms histograms of `intended_fix` and effective LED onset. Each histogram is proportionally scaled to a total of 5,500 trials using largest-remainder integer rounding. These are the two target marginal distributions.

For each of s7 OFF, s7 ON, s8 OFF, and s8 ON, the graph contains:

| Graph element | Value supplied | Meaning |
| --- | ---: | --- |
| Target `intended_fix` node | Negative demand equal to its target bin count | Supplies the requested number of trials from that session-type-9 bin |
| Candidate `intended_fix` node | Zero demand | Represents one s7/s8 20 ms `intended_fix` bin |
| Candidate LED-onset node | Zero demand | Represents one s7/s8 20 ms effective-onset bin |
| Target LED-onset node | Positive demand equal to its target bin count | Requires the requested number of trials in that session-type-9 onset bin |
| Target-intended to candidate-intended edge | Cost = absolute bin distance | Penalizes moving selected mass away from the target `intended_fix` distribution |
| Candidate-intended to candidate-onset edge | Capacity = number of real rows in that joint timing cell; cost = 0 | Prevents selection of more rows than actually exist with that timing pair |
| Candidate-onset to target-onset edge | Cost = absolute bin distance | Penalizes moving selected mass away from the target onset distribution |

One edge-cost unit is one 20 ms bin. The solver minimizes the sum of the intended-fix and onset movement costs while routing exactly 5,500 integer units through the graph. This is equivalent to minimizing the combined binned Wasserstein-1, or earth-mover, discrepancy of the two marginal distributions, subject to the observed joint-cell capacities.

If an exact simultaneous match is feasible, the minimum movement cost is zero. If it is not feasible because s7/s8 lack the required timing combinations, the solver finds the nearest feasible pair of marginal distributions. The final unbinned KS and Wasserstein distances are then checked explicitly.

### What the solver returns

The call returns:

```python
flow_cost, flow_by_edge = networkx.network_simplex(graph)
```

`flow_by_edge` contains integer amounts, not experimental rows. In particular:

```text
flow_by_edge[candidate_intended_bin][candidate_onset_bin]
```

is interpreted as the number of real rows to retain from that observed two-dimensional timing cell. For example, if a cell contains 100 available trials and its returned flow is 30, the analysis must keep 30 and remove 70 from that cell.

The identities of those 30 rows are then sampled once, without replacement, using the fixed seed `20260909`. Within a 20 ms × 20 ms cell the rows are equivalent to the matching objective, so this random step does not decide the cell quota. All rows not selected are removed from the matched subset.

### Pseudocode

```text
sample_size = 5,500
bin_width = 20 ms
seed = 20260909

data = rows satisfying:
    training_level == 16
    repeat_trial is 0, 2, or missing
    LED_trial is 0 or 1

for every row:
    if session_type is 7 or 8:
        effective_onset = intended_fix - LED_onset_time
    if session_type is 9:
        effective_onset = LED_onset_time

reference = pooled session-type-9 OFF and ON rows

target_intended_counts = largest_remainder_scale(
    histogram(reference.intended_fix, 20-ms bins),
    total=5,500,
)

target_onset_counts = largest_remainder_scale(
    histogram(reference.effective_onset, 20-ms bins),
    total=5,500,
)

for group in [s7 OFF, s7 ON, s8 OFF, s8 ON]:

    assign every candidate row to cell [i, j], where:
        i = its intended_fix bin
        j = its effective-onset bin

    available[i, j] = number of real candidate rows in cell [i, j]

    create directed graph

    for target intended bin a and candidate intended bin i:
        add edge target_intended[a] -> candidate_intended[i]
        edge cost = abs(a - i)

    for every observed candidate cell [i, j]:
        add edge candidate_intended[i] -> candidate_onset[j]
        edge capacity = available[i, j]
        edge cost = 0

    for candidate onset bin j and target onset bin b:
        add edge candidate_onset[j] -> target_onset[b]
        edge cost = abs(j - b)

    set target intended-bin supplies from target_intended_counts
    set target onset-bin demands from target_onset_counts

    flow_cost, flow_by_edge = network_simplex(graph)

    for every observed cell [i, j]:
        keep_count[i, j] = flow from candidate_intended[i]
                                      to candidate_onset[j]

        randomly retain keep_count[i, j] real rows from that cell
        using the fixed seed and sampling without replacement

    matched_group = union of retained rows from all cells

    verify:
        exactly 5,500 unique rows were retained
        intended_fix KS <= 0.015
        intended_fix Wasserstein <= 10 ms
        effective-onset KS <= 0.015
        effective-onset Wasserstein <= 10 ms

    only after matching:
        fixation_aborts = matched rows where abort_event == 3
```

Thus the solver decides the **number of rows retained per timing cell**. A separate fixed-seed draw decides the row identities within each cell. Neither stage uses `abort_event`, `timed_fix`, RT, ABL, ILD, choice, success, or response data.
